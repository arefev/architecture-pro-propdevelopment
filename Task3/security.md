# Внешние интеграции
## Требования к безопасности

1. Персональные данные и биометрия

- Передача и хранение биометрических данных (распознавание лица, номера автомобиля) должны соответствовать:
  - ФЗ-152 «О персональных данных»,
  - ФЗ-482 «О биометрических персональных данных» (если используется внешняя биометрическая платформа).
- Хранение биометрии вне контуров компании должно быть разрешено бизнесом и юридическим департаментом.
- Все данные, проходящие через интеграцию, должны быть строго ограничены необходимым минимумом (data minimization).

2. Шифрование

- Передача данных между мобильным приложением, backend PropDevelopment и системой партнёра должна происходить:
  - только по защищённым каналам (TLS 1.2+),
  - с обязательной проверкой серверных сертификатов.
- При необходимости — использование двустороннего TLS (mTLS) между backend PropDevelopment и внешней платформой.

3. Логи и аудит

- Все вызовы внешних API фиксируются в аудит-логах PropDevelopment.
- В логах запрещено хранить биометрию и полные номера автомобилей.
- Логи должны храниться в защищённом хранилище данных компании (домен «Дата»).

4. Изоляция интеграций

- Все запросы фильтруются через API-шлюз (WAF, rate limiting, throttling, защита от DDoS).

5. Контроль доступа пользователя

- Проверка прав доступа (собственник → объект недвижимости → входная дверь/домофон/шлагбаум) выполняется на стороне PropDevelopment, а не на стороне партнёра.
- Партнёр не должен самостоятельно принимать решение о доступе к объекту.

## Протоколы аутентификации и авторизации

Для интеграций используются следующие протоколы:

- OAuth 2.0 Client Credentials — для сервер-к-серверу интеграций (домофон, шлагбаум).
- mTLS — при передаче критичных данных (рекомендуется при работе с биометрией).

## Взаимодействие между системами предприятия и внешней платформой

Мобильное приложение → API PropDevelopment → API-шлюз → Партнёрская платформа

Шаги:

1. Пользователь совершает действие в мобильном приложении (например, открыть шлагбаум).

2. Приложение отправляет запрос в backend PropDevelopment, включая токен пользователя.

3. Backend:

- валидирует токен,
- проверяет права,
- определяет объект (дверь / шлагбаум),
- отправляет запрос партнёру.

4. Партнёр выполняет команду и возвращает результат.

Такая схема гарантирует:

- единый контроль данных,
- невозможность стороннего доступа,
- отсутствие прямой зависимости мобильного приложения от внешнего API.
